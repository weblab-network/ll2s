# LL2S 0.2.0-ovs-rstp1

This release includes an OVS 3.7.1 patch for incorrect RSTP root selection when
multiple incoming links advertise identical designated bridge and port IDs.
The lower-cost path now wins regardless of port iteration order. Received
information updates from the current neighbor retain their existing behavior.

We retested the original Cisco MST / LL2S RSTP topology and confirmed that the
lower-cost uplink is selected correctly. The fix also passes 18 native packet
replay checks using MST and RSTP BPDUs, four independent fresh starts, ten OVS
simulations, 44 LL2S unit/terminal tests and native switching/LLDP/recovery checks.
The packaged image passes a separate integration test including RSTP blocking,
LLDP, SNMP counters and saved Stop/Start restoration.

## Image and upgrade

```sh
docker pull ghcr.io/weblab-network/ll2s:0.2.0-ovs-rstp1
```

`latest` points to this build. The exact tested Linux amd64 image is
`sha256:0788adf74bf3fa460dc89e8da2a06a0cc824e16a3cdc1c190858038f7781bf0c`.
It is promoted without rebuilding; its original local-test labels and provenance
wording remain intact. LL2S Python still reports 0.2.0. The image version label
is `0.2.0-ovs-rstp1`, and `network.weblab.ll2s.ovs.rstp-root-vector=1` identifies
the included patch. The original `0.2.0` tag is preserved.

Save committed configuration with `write memory` before recreating a standalone
container, keeping its `/etc/ll2s` volume. Orchestrators may store configuration
separately for each image selector: export configuration and follow their normal
migration path. Updating a tag does not change a running container.

This corrects the reproduced root-selection defect; it does not add MSTP,
PVST+ or Rapid-PVST support. Broader vendor compatibility remains a separate test.
The OVS patch has not yet been accepted or submitted upstream.

## Sources and provenance

Release assets include the exact tested Docker image, `image.json`,
`ll2s-dependency-sources.tar.gz` and `SHA256SUMS`. The source bundle contains the
unchanged 0.2.0 runtime dependencies, verified against the full inherited APK
inventory, plus the source-built daemon's upstream archive, patch, exact build
recipe, toolchain metadata and OVS notices. The APK inventory alone describes
the base packages; `ovs-override/override.json` identifies the replaced daemon.

The [patch and original build recipe](../../packaging/ovs-rstp-test/README.md)
are also in this source tag. Default source builds include the correction.
Source/patch checksums are pinned; floating builder package revisions mean a fresh
build is not claimed to reproduce the binary byte for byte. The publication
workflow verifies the frozen binary/source pair against the committed release
lock before testing and pushing the image.
